1

Abrir o PowerShell como Administrador

Pressione Win + X e selecione Terminal (Admin) ou Windows PowerShell (Admin). Privilégios elevados são necessários para instalar ferramentas no sistema.

ⓘ No Windows 11 o atalho abre o Terminal do Windows. Certifique-se de que o perfil ativo é o PowerShell.
2

Instalar o Chocolatey

O Chocolatey é o gerenciador de pacotes do Windows. Execute os dois comandos abaixo no PowerShell Admin: 

# Habilitar execução de scripts
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser -Force

# Baixar e instalar o Chocolatey
Invoke-Expression ((New-Object System.Net.WebClient).DownloadString('https://community.chocolatey.org/install.ps1'))
ⓘ Chocolatey já instalado? Verifique a versão atual e faça o upgrade se necessário: 
# Verificar a versão instalada
choco --version

# Atualizar o Chocolatey para a versão mais recente
choco upgrade chocolatey -y
⚠ Após o upgrade, feche e reabra o PowerShell antes de continuar. As variáveis de ambiente (PATH) são atualizadas apenas em sessões novas. Alternativamente, atualize as variáveis sem fechar o terminal: 
# Opção 1 — se o perfil do Chocolatey já estiver carregado na sessão
refreshenv

# Opção 2 — se refreshenv não for reconhecido, importe o módulo primeiro
Import-Module "$env:ChocolateyInstall\helpers\chocolateyProfile.psm1"
refreshenv
3

Instalar as Ferramentas

Instale as três ferramentas uma por uma. O processo leva aproximadamente 15–20 minutos.

docker-desktop
Motor de containers — executa containers Docker localmente e serve de driver para o Minikube.
minikube
Sobe um cluster Kubernetes local de nó único, ideal para desenvolvimento e testes.
kubernetes-cli
Instala o kubectl, a CLI oficial para interagir com qualquer cluster Kubernetes.
choco install docker-desktop     -y --no-progress
choco install minikube           -y --no-progress
choco install kubernetes-cli     -y --no-progress
ⓘ O choco install minikube já instala o kubernetes-cli automaticamente como dependência. O terceiro comando é seguro de executar mesmo assim — se o kubectl já estiver instalado, o Chocolatey apenas informa e segue sem erros.
⚠ O docker-desktop solicita reinicialização ao final da instalação (exit code 3010). Conclua a instalação das três ferramentas antes de reiniciar.
4

Reiniciar e Verificar o Docker Desktop

⚠ Reinicie o computador antes de continuar. A instalação do Docker Desktop registra drivers e componentes de rede que só ficam ativos após o reboot (exit code 3010). Sem reiniciar, o minikube start vai falhar.

Após o reboot, verifique a bandeja do sistema (canto inferior direito da tela):

  • Se o ícone do Docker Desktop já estiver presente e estável — ele iniciou automaticamente com o Windows. ✅ Pode seguir para o próximo passo.
  • Se o ícone não estiver presente — abra o Docker Desktop manualmente pelo Menu Iniciar e aguarde 1–2 minutos até estabilizar.
🔎 Observação confirmada (docker-desktop v4.84.0 / Windows 11 Enterprise 25H2): o Docker Desktop não iniciou automaticamente após o reboot — o ícone não apareceu na bandeja do sistema e o serviço com.docker.service permaneceu com status Stopped / StartType: Manual. Não há entrada de autostart em HKCU\…\Run nem em HKLM\…\Run para o Docker Desktop nessa instalação via Chocolatey. Foi necessário abri-lo manualmente pelo Menu Iniciar antes de executar o minikube start. Se quiser que ele inicie automaticamente, habilite a opção em Docker Desktop → Settings → General → Start Docker Desktop when you sign in.
ⓘ Por padrão o Docker Desktop se configura para iniciar com o Windows, mas esse comportamento não se aplicou nesta instalação — veja observação acima.
⚠ O Minikube usa o Docker como driver. Se o Docker Desktop não estiver rodando, o próximo passo vai falhar.
5

Iniciar o Minikube

Abra um novo PowerShell sem privilégios de admin e execute: 

minikube start --cpus=2 --memory=2048 --driver=docker

Isso cria um cluster Kubernetes local com 2 CPUs e 2 GB de RAM, usando o Docker Desktop como backend.

6

Verificar o Cluster

Confirme que o cluster está ativo e saudável com os comandos abaixo:

# Exibe a URL do control-plane
kubectl cluster-info

# Lista os nós (deve aparecer "minikube   Ready")
kubectl get nodes

# Lista os 7 pods do sistema — todos devem estar "Running"
kubectl get pods -n kube-system
✓ Se o nó aparecer com status Ready e os 7 pods do kube-system com status Running, seu ambiente está pronto para uso!
✅ Validado com sucesso — minikube v1.38.1 · kubernetes-cli v1.36.3 · docker-desktop v4.84.0 · Windows 11 Enterprise 25H2:
kubectl cluster-info → Kubernetes control plane is running at https://127.0.0.1:57047
kubectl get nodes → minikube   Ready   control-plane   v1.35.1   docker://29.2.1
7

Validar o Ambiente — Testes End-to-End

Com o cluster rodando, execute os testes abaixo para confirmar que o ambiente funciona de ponta a ponta. São dois níveis progressivos.

🔵 Nível 1 — Cluster básico

Confirme que o cluster responde corretamente a consultas simples:

# O nó deve aparecer como "Ready"
kubectl get nodes

# Deve mostrar a URL do control-plane
kubectl cluster-info

# Deve listar 7 pods todos "Running"
kubectl get pods -n kube-system

🔵 Nível 2 — Deploy real de uma aplicação

O teste mais direto: subir um container e acessá-lo no navegador:

# Faz deploy de um nginx
kubectl create deployment nginx --image=nginx

# Expõe na porta 80 via NodePort
kubectl expose deployment nginx --type=NodePort --port=80

# Aguarda o pod ficar Ready
kubectl rollout status deployment/nginx

# Obtém a URL para acessar no navegador
minikube service nginx --url
ⓘ Abra a URL retornada no navegador. Deve aparecer a página "Welcome to nginx!". Se aparecer, o ambiente está 100% funcional end-to-end.
⚠ Após os testes, remova os recursos criados para manter o cluster limpo: 
kubectl delete deployment nginx
kubectl delete service nginx
